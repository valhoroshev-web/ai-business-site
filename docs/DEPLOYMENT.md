# Запуск и настройка AI PROFI

## Проект

- GitHub: https://github.com/valhoroshev-web/ai-business-site
- Vercel: https://vercel.com/valhoroshev-web/ai-business-site
- Временный адрес: https://ai-business-site-tau.vercel.app
- Планируемый домен: https://ai-profi.pro

Репозиторий Next.js, production-развёртывание из ветки `main`. В разделе контактов доступны **две карточки с иконками**: Telegram и электронная почта. После выбора канала и короткой CAPTCHA открывается нужный контакт. Имя пользователя и email не передаются в исходном HTML или клиентском JavaScript до успешной проверки.

## Форма обратной связи

Отдельная серверная форма заявок содержит имя, контакт, компанию (необязательно), описание задачи, согласие на обработку данных и Cloudflare Turnstile. CAPTCHA раскрытия контактов не относится к этой форме.

- По умолчанию автоматическая отправка заявки выключена, а на сайте показан неактивный предварительный вид формы. Карточки каналов связи работают независимо от настройки отправки заявок, если настроены три переменные раскрытия контактов (ниже).
- Если настроен Resend, отправка идёт **на приватный адрес** из `RESEND_TO_EMAIL` через Resend API.
- Если Resend не настроен, но указаны Telegram Bot API ключи, отправка идёт **через бота** в указанный чат.
- Если оба канала настроены, приоритет у email; **двойная доставка не выполняется**.
- Если провайдер не принял сообщение, посетителю не выдаётся подтверждение.
- Если провайдер ответил успешно, сообщение принято им к обработке; это не гарантирует попадание письма во входящие Gmail.
- Заявки не сохраняются в базе сайта. У провайдеров могут быть собственные журналы и сроки хранения.

## Доступ к Telegram и почте после CAPTCHA

В разделе контактов посетитель видит **иконку Telegram** и **иконку конверта** без номера, ника или email. По нажатию открывается диалог с простым примером сложения; правильный ответ проверяется **на сервере** с помощью HMAC-подписи. Токен действует 5 минут.

В Vercel → ai-business-site → Settings → Environment Variables → Production добавьте:

- `CONTACT_TELEGRAM_USERNAME` — ник Telegram без `@` (личный адрес, не публиковать в GitHub).
- `CONTACT_EMAIL` — адрес, на который пользователь может написать напрямую после CAPTCHA.
- `CONTACT_CAPTCHA_SECRET` — случайный секрет длиной от 24 символов (предпочтительно 32+ байт криптографически случайных данных), не показывать пользователям и не вносить в GitHub.

После обновления переменных выполните **Redeploy**. Тест: нажать Telegram → решить задачу → перейти в чат; аналогично открыть почтовый адрес и `mailto:`. Неверный или просроченный ответ не раскрывает адрес.

Это мера против простого автоматического сбора контактов, а не абсолютная защита: мотивированный бот может решать простую CAPTCHA. Для существенного ограничения перебора следует дополнительно использовать rate limiting / WAF.

Секреты отправки заявок Resend и Telegram-бота для этого шага **не нужны**.

## 1. Подключение отправки на email (Resend)

1. Создайте аккаунт в [Resend](https://resend.com/).
2. В [Domains](https://resend.com/domains) добавьте **поддомен** `notify.ai-profi.pro` (либо другой принадлежащий вам домен/поддомен). Отдельный поддомен уменьшает риск конфликтов с текущей почтой.
3. Resend покажет DNS-записи для подтверждения отправителя: точные типы, имена и значения берите **из Resend**, не копируйте произвольные примеры.
4. В REG.RU DNS управляется через зону с NS `ns1.hosting.reg.ru` / `ns2.hosting.reg.ru` в ispmanager. **Не изменяйте A-запись сайта и MX-записи существующей почты**. Добавьте только необходимые записи для выбранного поддомена, проверяя возможные конфликты.
5. Дождитесь статуса `Verified` для домена в Resend.
6. В [Resend API Keys](https://resend.com/api-keys) создайте ключ с разрешением отправки писем.
7. В Vercel → Project → Settings → Environment Variables → Production добавьте:
   - `RESEND_API_KEY` — **секретный** ключ из Resend, не включать в исходный код.
   - `RESEND_FROM_EMAIL` — подтверждённый адрес отправителя, пример **только после верификации поддомена**: `AI PROFI <leads@notify.ai-profi.pro>`.
   - `RESEND_TO_EMAIL` — приватный адрес получателя заявок; **обязателен**, не публикуется в исходном коде.
8. Не используйте в качестве `from` личный Gmail: для отправителя требуется подтверждённый домен, а личная почта используется только как получатель через `RESEND_TO_EMAIL`.

Сервер использует `POST https://api.resend.com/emails` и отправляет только текст сообщения. При наличии корректного email у клиента он задаётся как `reply_to`, не `from`.

## 2. Cloudflare Turnstile — защита от спама

1. В Cloudflare Turnstile создайте виджет для домена, на котором действительно открывается форма. Укажите `ai-profi.pro` и/или `ai-business-site-tau.vercel.app` по фактическому использованию.
2. Добавьте в Vercel Production:
   - `NEXT_PUBLIC_TURNSTILE_SITE_KEY` — публичный ключ виджета.
   - `TURNSTILE_SECRET_KEY` — секретный ключ для проверки на сервере.
3. Браузер передаёт токен, сервер проверяет его через Cloudflare Siteverify и сверяет hostname. Без успешной проверки заявка не отправляется.
4. CAPTCHA раскрытия контактов независима от Cloudflare Turnstile. Две иконки — это **кнопки выбора канала**, а не варианты ответа на CAPTCHA. После нажатия пользователь получает короткий арифметический вопрос.

## 3. Юридическая часть — обязательно до активации

Страница `/privacy` пока содержит **шаблон**, а не утверждённую политику. Перед приёмом персональных данных требуется определить оператора, применимое законодательство, место размещения и передачи данных, основания и сроки обработки, условия взаимодействия с Cloudflare, Vercel и Resend / Telegram, а затем опубликовать юридически проверенный документ.

После этого:
- `LEGAL_OPERATOR_NAME` — юридически верное полное наименование/ФИО оператора;
- `LEGAL_OPERATOR_ADDRESS` — адрес, который требуется раскрыть по применимым правилам;
- `LEGAL_CONTACT_EMAIL` — отдельный адрес обработки запросов по персональным данным, указывается в приватных настройках; юридическую корректность способа связи нужно проверить;
- `LEGAL_POLICY_APPROVED=true` — **только после** замены шаблона утверждённой политикой и юридической проверки.

В зависимости от аудитории и географии обработки могут применяться дополнительные обязанности, в том числе в отношении трансграничной передачи данных. Не считайте наличие технической формы подтверждением правовой готовности.

## 4. Включение формы

Добавьте `LEADS_ENABLED=true` **только после** завершения всех предыдущих этапов. Форма появляется активной, только когда одновременно присутствуют:

`LEADS_ENABLED=true` + `LEGAL_POLICY_APPROVED=true` + Resend **или** Telegram credential pair + Turnstile keys + LEGAL operator name/email/address.

Все секреты указываются в **Vercel Environment Variables**, не в GitHub и не в чате. Затем выполните **Redeploy**.

Проверьте самостоятельно:
1. Отправку тестовой заявки с разрешёнными тестовыми данными на опубликованном домене, включая выбор иконки и проверку Turnstile.
2. Получение письма в почтовом ящике из `RESEND_TO_EMAIL`, включая «Спам». Успешный HTTP-ответ Resend — не окончательное подтверждение доставки.
3. Ошибку без согласия на обработку, без Turnstile, с неверной или просроченной иконкой и с недопустимыми полями — заявка не должна уходить.
4. Поведение на телефоне, корректность ссылок и состояние после ошибки доставки.

## 5. Аналитика и SEO

Яндекс Метрика включается только после отдельного согласия посетителя и установки `NEXT_PUBLIC_YANDEX_METRIKA_ID`. Цель для успешной заявки: `lead_submitted`.

Индексация по умолчанию выключена (`SITE_READY_FOR_INDEXING` отсутствует или равна `false`). Перед запуском SEO:
- завершите юридическую часть, контакты и форму;
- проверьте домен `ai-profi.pro` и HTTPS в Vercel;
- установите `NEXT_PUBLIC_SITE_URL=https://ai-profi.pro`;
- после проверки включите `SITE_READY_FOR_INDEXING=true`;
- выполните Redeploy, проверьте `robots.txt`, `sitemap.xml`, canonical.

Не включайте индексацию автоматически только из-за наличия формы.


## 6. Ограничение видимости контактов

- Публичные страницы показывают только иконки каналов и текстовую подсказку.
- Личные контактные данные хранятся в закрытых переменных Vercel и выдаются сервером только после успешной проверки CAPTCHA.
- Если поля окружения не заданы, выбранный канал сообщает о незавершённой настройке.
- После успешной проверки email/ник становятся доступными конкретному посетителю, поэтому абсолютная защита от целенаправленного сбора невозможна.
- Ранее опубликованные контакты могут оставаться в истории GitHub, поисковых кешах и скопированных страницах.
- Публикацию обязательных юридических реквизитов оператора необходимо отдельно согласовать с применимым законодательством.
