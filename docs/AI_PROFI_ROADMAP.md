# AI PROFI — программа развития каталога ИИ-решений

Дата постановки: 24.11.2026. Базовая опубликованная версия: GitHub main 88b9ed6.

## Цель
Создать постоянно пополняемую библиотеку реальных *возможных* применений ИИ для бизнеса, из которой посетитель может перейти к услугам внедрения. Не выдавать концепты за выполненные кейсы.

## Этап A. Каталог и первая публикация — код подготовлен в PR #14
- [x] 30 различающихся практических сценариев и классификация по направлениям/отраслям.
- [x] Страница каталога, текстовый поиск, фильтры, результат без совпадений.
- [x] Отдельная индексируемая *после активации* страница каждого сценария: проблема, входные данные, этапы, роль человека, критерии пилота и ограничения.
- [x] Ссылки на каталог с главной страницы и меню.
- [x] Canonical, индивидуальные метаданные, BreadcrumbList, sitemap (пока заблокирован флагом готовности).
- [x] Код событий для Метрики после согласия: каталог, демонстрации, контакты.
- [ ] Проверка CI и визуальная проверка мобильной версии.
- [ ] Юридическая редактура текстов и финальная сверка 30 сценариев профильным специалистом.
- [ ] Подтверждение владельца сайта в вебмастерах и настройка счётчика.
- [ ] Финальное разрешение на индексацию после правовых проверок.

## Этап B. Углубление и подтверждение коммерческой модели
- [ ] Сформировать рубрикатор поисковых запросов на основе **реальных** выгрузок Wordstat/Вебмастера/Search Console, а не выдуманных частотностей.
- [ ] Провести редакторскую ревизию первых 30 страниц по полезности и конкретности.
- [ ] Расширить 10 лучших сценариев: пример исходного документа, пример результата, интеграционная схема, метод оценки стоимости и риска.
- [ ] Определить форматы коммерческого предложения: диагностика / пилот / внедрение и сопровождение.
- [ ] Реальный ИИ-прототип (не сценарный симулятор) запускать только после выбора API-провайдера, бюджетного лимита, фильтров ввода, согласованных правил обработки данных и требований безопасности.
- [ ] Внести достоверные сведения об исполнителе и документально подтверждённый опыт, без придуманных логотипов и отзывов.

## Этап C. Масштабирование по фактам
- [ ] Расширить библиотеку до 50–80 материалов при положительных сигналах по органическому спросу и качеству контента.
- [ ] Сделать отдельные тематические подборки и связи между близкими сценариями.
- [ ] Цель 100–200 страниц рассматривать как условную — публиковать новые только при уникальном запросе, новых данных и редакторском контроле.
- [ ] Регулярная проверка позиций, индексирования, доли обращений и прибыли по типу сценария.

## Политика публикации
Только после тестов / ручной проверки. Не публиковать пустые заготовки, маскируя их под истории клиентов. Не утверждать фактическую экономию без измерений. Не менять боевой main без завершения проверок. Не включать SITE_READY_FOR_INDEXING до утверждения юридических документов.
